1. Title & Problem Definition

Innov CRM: Streamlining B2B Sales Cycles by Eliminating Manual SLA Dispatch Gaps and Multi-User Stage Collisions

Context & Background

Enterprise sales teams handle dozens of high-value deals concurrently. Representatives spent roughly 2.5 to 3 hours daily manually recording stage changes and writing email updates, leaving them less time to focus on active selling.

Problem Statement

How might we design a fast sales pipeline workspace that automates administrative tasks and keeps data consistent when multiple agents update the same records simultaneously?

Research & Insights

During shadowing sessions, we discovered two core issues:

  • SLA Drop-offs: 42% of sales leads went cold because representatives forgot to send follow-up details when a deal was moved to the "Contacted" stage.
  • Database Race Conditions: When two representatives dragged the same deal card at the same time, database writes clashed, resulting in duplicate tasks and broken statuses.

Solution & Reasoning

We built an interactive Kanban pipeline dashboard backed by an event-driven task listener. Moving a card to a new column automatically triggers the corresponding SLA task.

To solve write clashes without slowing down the UI, we used an optimistic locking database schema. When a collision occurs, the system flags it in the UI and resolves it safely instead of freezing the database connection.

Learnings & Tradeoffs

Optimistic locking was chosen over pessimistic locking because sales reps rarely edit the exact same deal card at the exact same millisecond. Choosing optimistic locking avoided database thread blockage and preserved rapid write speeds.

1. Title & Problem Definition

ModelMetrics: Building an Interactive PCA Telemetry Dashboard to Simplify High-Value Customer Segmentation

Context & Background

Growth marketing teams need to divide users into segments to run targeted campaigns. In most companies, this requires writing complex SQL queries or asking data engineers to run localized Python notebooks.

Problem Statement

How might we give non-technical marketing leads a visual tool to explore multi-dimensional customer segments without waiting for manual CSV exports?

Research & Insights

Shadowing data scientists and growth leads revealed a clear bottleneck:

  • Slow Turnaround Times: 80% of marketing campaigns were delayed because teams had to wait up to a week for data analysts to extract cohort segments.
  • Difficult Visualizations: Standard dashboards showed static charts but did not let users interact with multi-dimensional datasets directly.

Solution & Reasoning

We built an interactive 2D scatter plot interface representing Principal Component Analysis (PCA) clustering. Marketers can draw bounding boxes directly over visual clusters to isolate specific cohorts. A webhook action then pushes the selected cohort directly to marketing tools.

Learnings & Tradeoffs

We chose to render the PCA chart on the client-side using lightweight Canvas drawing rather than SVG nodes. This maintained a fluid 60fps frame rate even when loading tens of thousands of data points, though it meant losing built-in CSS transitions on individual nodes.

1. Title & Problem Definition

MarketingOS: Consolidating fragmented ad campaign cohorts and tracking real-time Lead Response Time

Context & Background

Performance marketing managers rely on multiple ad networks to acquire customers. They have to log into separate platforms to measure daily conversions, making optimization slow and manual.

Problem Statement

How might we unify ad campaign analytics into a single dashboard to track cohort performance and Lead Response Time in real-time?

Research & Insights

Interviews with growth leads highlighted two major inefficiencies:

  • Manual Overhead: Marketing specialists spent an average of 3.5 hours every morning copying and pasting campaign data into Excel sheets.
  • Ad Spend Leakage: Fragmented data delayed campaign optimization, resulting in up to 15% wasted budget on non-converting ad groups.

Solution & Reasoning

We built a multi-tenant workspace analytics dashboard that aggregates conversion metrics and tracks Lead Response Time (LRT) in real-time. By connecting data pipelines directly to active ad networks, we removed the need for manual reports.

We prioritized daily conversion freshness over historical cold storage. Cohort queries are served from Redis cache layers, which speeds up real-time insights but caps retro-analyses to 90 days.

1. Title & Problem Definition

researchOS: Moving scholarly searches from raw keywords to context-aware semantic space matching

Context & Background

Academic researchers query thousands of papers. Traditional keyword search systems frequently miss relevant work because they do not understand the conceptual context behind different terms.

Problem Statement

How might we build a semantic search system that retrieves contextually relevant research papers and reduces empty results?

Research & Insights

Analyzing user queries and results revealed clear search barriers:

  • High Rate of Empty Results: 31% of academic queries returned no results because users wrote descriptive questions instead of exact matching terms.
  • Fragmented Terminology: Search engines missed up to half of relevant papers because authors used different terminologies for the same core concepts.

Solution & Reasoning

We built a semantic RAG (Retrieval-Augmented Generation) search pipeline. It translates user queries into vector space embeddings and searches papers based on conceptual distance, solving the limitations of keyword matching.
